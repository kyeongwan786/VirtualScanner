NEW_WORK V2 Windows 빌드 안내
============================

V2 중앙 앱은 중앙 PC에서 OCR 결과와 PDF 작업을 검토한 뒤 선택한 접수 PC의
V2 Receiver로 Relay 전송합니다.

중앙 미리보기의 idCrop/CR.jpg 선택 박스는 기존 코드 크기 규격을 따릅니다:
유형 1001은 340×406, 그 외 유형은 320×420입니다. 선택한 원본 영역을 해당 크기로
저장하며 SK idCrop은 지원 유형에만 기록합니다.

Receiver가 작업 적용을 완료하면 송신 화면과 해당 작업의 임시 자료를 자동 초기화해
다음 건을 바로 시작합니다. 신분증 JPG는 왼쪽 OCR 영역에, PDF는 오른쪽 서류 영역에
드래그앤드롭할 수 있습니다. 포탈과 접수 PC 선택은 유지됩니다.

신분증만, PDF만, 두 자료를 함께 각각 전송할 수 있습니다. PDF만 보낸 경우 Receiver는
SK/KT 결과를 건드리지 않고 PDF 서류만 대기열에 등록합니다. 단, Receiver는 새 패키지
수신 때 기존 수신 작업과 ready 대기열을 자동 교체하므로, 새 한쪽짜리 작업도 이전
패키지와 대기열을 정리합니다.

빌드
----
Windows x64에서 Python 3.12 x64를 설치하고 build_windows.bat을 실행하세요.
성공하면 dist\new_work\new_work.exe가 생성됩니다.
이 ZIP은 빌드 소스이며 완성된 Windows EXE를 포함하지 않습니다.

실행 전에 Relay와 접수 PC의 자리 ID/토큰을 설정하고, 대상 접수 PC에서 V2
Receiver가 실행 중인지 확인하세요. 상세한 설정은 RECEIVER_README.md를 보세요.

전송 취소·초기화
----------------
V2 화면의 “전송 취소·초기화”는 진행 중 업로드나 Receiver 적용 대기 작업의
Relay 취소를 요청하고 현재 작업 화면 및 앱이 만든 임시 신분증 사본, PDF 페이지,
전송 ZIP을 정리합니다. 원본 신분증/JPG/PDF는 삭제하지 않습니다. 이미 Receiver가
작업을 적용한 뒤에는 취소할 수 없으며, Relay 응답 중인 요청이 끝난 다음 초기화됩니다.

OCR 실행 중이거나 PDF 변환 중에도 “선택 PC로 저장”을 먼저 누를 수 있습니다. 이 경우 전송을 예약하고 OCR 및 추가한 모든 PDF 변환이 성공하면 자동으로 ZIP 전송을 시작합니다. 예약 뒤에는 새 신분증/PDF를 추가하거나 대상을 바꾸지 못하며, 실패 시 자동 전송은 취소되고 화면에 원인이 표시됩니다.

주민번호 OCR 후보가 체크섬 검증에 실패하면 후보를 화면에 남겨 직접 수정하도록 합니다. 한국어 숫자 인식이 실패하면 숫자 줄만 영문 인식기로 다시 읽고, 두 이미지 보정 결과가 같은 유효 번호를 낼 때만 자동 입력합니다. 그래도 인식이 불확실하면 유효한 번호로 고치기 전에는 저장/전송을 진행하지 않습니다.
