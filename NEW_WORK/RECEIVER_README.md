# NEW_WORK Receiver V3

이 Receiver는 중앙 OCR V3의 선택 PC 전송을 받는다. 중앙 OCR V1은 실행 PC에 직접
SK/KT 결과를 적용하므로 Receiver가 필요하지 않다.

NEW_WORK central and Receiver use the existing `KyeongwanReceiver` HTTPS relay. The central PC uploads its already prepared ZIP as one archive (split into 40 MiB chunks only when needed), with reviewed portal metadata. Receiver downloads and verifies that ZIP, stores it in a local folder, then acknowledges receipt. It does not write SK/KT portal data on arrival: the operator reviews the identity type and presses **신분증 확인** in Receiver first. PDF-only packages are acknowledged after local storage and never change SK/KT identity data. This replaces one relay upload and download request per image. It does not require an SMB share or an inbound port on the intake PC.

## Relay service

The deployed Render service is `https://kyeongwan-relay-test.onrender.com`. Its `/health` endpoint reports the relay features. The service uses HTTPS (TCP underneath); central and Receiver PCs make outbound connections, so no inbound port forwarding is needed.

Render settings must contain:

- `KYEONGWAN_RELAY_CENTRAL_TOKEN`: a random token at least 32 characters long.
- `KYEONGWAN_RELAY_STATIONS`: a JSON array with each exact `station_id` and its unique random token, for example `[ {"station_id":"desk-01","token":"a-long-random-station-token"} ]`.
- `KYEONGWAN_RELAY_DATA_KEY`: a Fernet key generated by Render or provisioned securely.

The Render service is HTTPS. The network transport uses TCP underneath HTTPS; Receiver PCs make outbound polling connections, so they do not need inbound ports or port forwarding. The relay encrypts queued ZIP chunks at rest and removes the archive payload after Receiver acknowledges local receipt. The central app requires the `/health` feature `new-work-zip-v1`; deploy the updated `KyeongwanReceiver/relay_server.py`, then install updated central and Receiver builds before sending. Older Receiver builds do not see ZIP jobs. The existing Render free plan uses temporary storage and is not a durable production queue. Do not send real intake documents through a free test deployment.

## Configure the central PC

1. Start the NEW_WORK central app and choose **Relay 서버**.
2. Enter the Render HTTPS origin, such as `https://kyeongwan-relay-test.onrender.com`, and the central token. The app stores this in the current user's NEW_WORK settings.
3. Open **접점 설정** for each workstation and enter its exact Render `station_id` in **Render Relay 자리 ID**. This value must match both Render's station list and that workstation's Receiver setting.
4. Select a workstation, add an identity JPG, PDFs, or both, then choose **선택 PC로 저장**. OCR and PDF conversion finish before the package uploads. The sender reports success when Receiver safely stores the package; for an identity, the operator must still press **신분증 확인** on Receiver to write SK/KT portal data. If it times out after upload, do not resend the same intake until Receiver status is checked.

In the central identity preview, drag the blue `idCrop`/`CR.jpg` box to move it. Its size is fixed for the selected identity type and cannot be resized. Drag outside the box to place the same fixed-size region at a new position. **자동 영역 복원** returns to the detected crop. The selected source-image coordinates travel with the work package: central SK generation uses them for the Base64 `idCrop`, and Receiver KT generation uses them for `CR.jpg`. The normal portal output dimensions are retained. Receiver PCs must run a build containing the crop-coordinate support for manual KT regions to take effect.

## Start and configure a workstation Receiver

On the Windows intake PC, run from a Windows checkout of this repository:

```powershell
cd C:\path\to\VirtualScanner\NEW_WORK
python -m pip install -r requirements_receiver.txt
python .\receiver_run.py
```

For a standalone Receiver app without the central OCR dependencies, use the Receiver-specific build files on Windows:

```powershell
.\build_receiver_windows_v3.bat
```

The package is also available through `NEW_WORK-Receiver-V3-Windows-Build.zip`. Run `dist\new_work_receiver_v3\new_work_receiver_v3.exe`. In **Receiver 설정**, enter:

- Render Relay HTTPS address.
- `station_id` exactly as configured in Render and the central workstation entry.
- This station's unique token from `KYEONGWAN_RELAY_STATIONS`.
- This PC's local `sk_report.txt`, `myCustomer.db`, KT image folder, and virtual scanner `ready` folder.
- A local Receiver work folder for retained jobs and backups.

Receiver polls every two seconds when the GUI is open. During download, it shows progress, rate, and estimated remaining time. Keep Receiver running while the central PC sends work. Acknowledgement means the complete job was verified and saved locally; it does not mean that SK/KT was updated. Portal saving happens only after the operator presses **신분증 확인** on the selected folder.

**받은 자료 초기화** clears this Receiver's local received job packages, including identity JPGs, OCR values, PDF page JPGs, manifests, the saved scan/wait/completed lists, in-memory previews, and all job contents of the configured scanner `ready` folder. It can be confirmed while scanning or receiving. An in-flight Relay receive is cancelled before cleanup. A scan may fail when its `ready` files are removed. It does not delete already-applied SK/KT target files or their backups, or jobs still waiting at Relay. The confirmation dialog shows the `ready` path and deletion scope.

Receiving another package adds another folder and keeps existing received folders and scanner queues. This lets staff sort multiple intake requests independently. Use **받은 자료 초기화** only when you intend to delete retained folders and scanner `ready` contents; the confirmation dialog lists the paths and deletion scope.

## Receiver screen and local PDF scan queue

The Receiver opens one HTML/CSS dashboard with received folders on the left and the selected folder on the right. It shows the identity preview and identity type only; OCR result fields are omitted because the sender reviewed them. Press **신분증 확인** to apply that folder's reviewed result. The panel then shows **신분증 확인 완료**. SK writes the configured `sk_report.txt` with a timestamped backup. KT updates the configured database and generates `ORG.jpg` and `CR.jpg`, keeping its database and image backups. When a folder has no identity or no PDFs, the page explicitly shows **받은 신분증이 없습니다** or **받은 PDF 서류가 없습니다**.

The sender converts PDFs to JPG pages before transfer; Receiver stores and scans those JPGs. Each original PDF is kept as a grouping label, while the row displays the converted JPG page thumbnails and count. Click a thumbnail to page through the images. A new image group starts waiting. Press **스캔 대기열에 추가** to copy only that group's pages to `ready`; its status changes to **스캔 대기 중** and the button becomes **스캔 취소**. Cancel moves it back to waiting and removes only its staged copy from `ready`. If TWAIN is already acquiring that group, the current scan may fail. Completed groups show **스캔 완료**.

Select folders in either list and press **Delete**, or use **선택 서류 삭제**. The Receiver moves their page folders into a local per-job trash folder and removes them from both lists. Press **Ctrl+Z** or **삭제 취소** to restore the most recent deletion; the undo history survives a Receiver restart. Documents currently being scanned cannot be deleted. **서류 목록 초기화** permanently removes listed and trashed document pages and clears the undo history.

**서류 목록 초기화** asks for confirmation, blocks while the scanner `ready` folder has a job, then permanently deletes PDF page JPGs (including trashed pages) and clears those PDF entries from their local manifests. It keeps identity images, OCR values, SK report files, KT databases, and the scanner folder. This reset cannot be undone.

Folder names are normalized for display so Korean filenames created on macOS do not appear as separated consonants and vowels in the Windows Receiver.

The Receiver UI uses HTML/CSS in a pywebview desktop window and can also run on macOS from source with `NEW_WORK/run_receiver_macos.command`, or be packaged as a Mac app with `NEW_WORK/build_receiver_macos.command`. Both use the same folder dashboard for Relay receipt, identity confirmation, page preview, and local queue management. TWAIN acquisition is Windows-specific and must be used on a Windows workstation for actual business-page scanning.

Identity images, reviewed OCR values, received job folders, previous SK reports, KT database backups, and scanner queue data remain on the workstations until explicitly reset or normally completed. The Render relay is a separate cloud copy: its page payload is deleted after Receiver confirms local receipt, while a small status record remains so the central app can confirm delivery.
