# NEW_WORK Receiver V2

이 Receiver는 중앙 OCR V2의 선택 PC 전송을 받는다. 중앙 OCR V1은 실행 PC에 직접
SK/KT 결과를 적용하므로 Receiver가 필요하지 않다.

NEW_WORK central and Receiver use the existing `KyeongwanReceiver` HTTPS relay. The central PC uploads its already prepared ZIP as one archive (split into 40 MiB chunks only when needed), with reviewed portal metadata. Receiver downloads and verifies that ZIP, extracts the JPGs locally, applies SK or KT data, and acknowledges only after local application succeeds. This replaces one relay upload and download request per image. It does not require an SMB share or an inbound port on the intake PC.

## Relay service

The deployed Render service is `https://kyeongwan-relay-test.onrender.com`. Its `/health` endpoint reports the relay features. The service uses HTTPS (TCP underneath); central and Receiver PCs make outbound connections, so no inbound port forwarding is needed.

Render settings must contain:

- `KYEONGWAN_RELAY_CENTRAL_TOKEN`: a random token at least 32 characters long.
- `KYEONGWAN_RELAY_STATIONS`: a JSON array with each exact `station_id` and its unique random token, for example `[ {"station_id":"desk-01","token":"a-long-random-station-token"} ]`.
- `KYEONGWAN_RELAY_DATA_KEY`: a Fernet key generated by Render or provisioned securely.

The Render service is HTTPS. The network transport uses TCP underneath HTTPS; Receiver PCs make outbound polling connections, so they do not need inbound ports or port forwarding. The relay encrypts queued ZIP chunks at rest and removes the archive payload after Receiver acknowledges local application. The central app requires the `/health` feature `new-work-zip-v1`; deploy the updated `KyeongwanReceiver/relay_server.py`, then install updated central and Receiver builds before sending. Older Receiver builds do not see ZIP jobs. The existing Render free plan uses temporary storage and is not a durable production queue. Do not send real intake documents through a free test deployment.

## Configure the central PC

1. Start the NEW_WORK central app and choose **Relay 서버**.
2. Enter the Render HTTPS origin, such as `https://kyeongwan-relay-test.onrender.com`, and the central token. The app stores this in the current user's NEW_WORK settings.
3. Open **접점 설정** for each workstation and enter its exact Render `station_id` in **Render Relay 자리 ID**. This value must match both Render's station list and that workstation's Receiver setting.
4. Select a portal and workstation, load the identity JPG and PDFs, then choose **선택 PC로 저장**. You can press it while OCR or PDF conversion is still running: the V2 app queues the send and starts uploading automatically after OCR and every added PDF finish successfully. The app waits for the selected Receiver to apply the work package and acknowledge it. If it times out after upload, do not resend the same intake until Receiver status is checked.

In the central identity preview, drag the blue `idCrop`/`CR.jpg` box to move it. Its size is fixed for the selected identity type and cannot be resized. Drag outside the box to place the same fixed-size region at a new position. **자동 영역 복원** returns to the detected crop. The selected source-image coordinates travel with the work package: central SK generation uses them for the Base64 `idCrop`, and Receiver KT generation uses them for `CR.jpg`. The normal portal output dimensions are retained. Receiver PCs must run a build containing the crop-coordinate support for manual KT regions to take effect.

## Start and configure a workstation Receiver

On the Windows intake PC, run from a Windows checkout of this repository:

```powershell
cd C:\path\to\VirtualScanner\NEW_WORK
python -m pip install -r requirements.txt
python .\receiver_run.py
```

For a standalone Receiver app without the central OCR dependencies, use the Receiver-specific build files on Windows:

```powershell
.\build_receiver_windows.bat
```

The package is also available through `NEW_WORK-Receiver-Windows-Build.zip`. Run `dist\new_work_receiver\new_work_receiver.exe`. In **Receiver 설정**, enter:

- Render Relay HTTPS address.
- `station_id` exactly as configured in Render and the central workstation entry.
- This station's unique token from `KYEONGWAN_RELAY_STATIONS`.
- This PC's local `sk_report.txt`, `myCustomer.db`, KT image folder, and virtual scanner `ready` folder.
- A local Receiver work folder for retained jobs and backups.

Receiver polls every two seconds when the GUI is open, so a newly completed relay upload waits at most about two seconds for the next check, plus network and local apply time. During download, Receiver shows a horizontal progress bar with downloaded size, current rate, percent, and an approximate remaining time based on the measured download rate. The estimate covers Relay-to-Receiver transfer; ZIP verification, extraction, and applying SK/KT data happen afterward. The central sender checks for the Receiver's completion acknowledgement every second. Keep the Receiver running while the central PC sends work. The Receiver stores the complete job locally before applying data; SK replaces the configured report with a timestamped backup, and KT updates the configured local database and image folder. Only after that succeeds does it acknowledge the relay. A failed application stays queued at the relay and Receiver retries after a pause.

**받은 자료 초기화** clears this Receiver's local received job packages, including identity JPGs, OCR values, PDF page JPGs, manifests, the saved scan/wait/completed lists, in-memory previews, and all job contents of the configured scanner `ready` folder. It can be confirmed while scanning or receiving. An in-flight page request is allowed to finish before local cleanup; if application has already started, that application and its Relay acknowledgement finish first. A scan may fail when its `ready` files are removed. It does not delete already-applied SK/KT target files or their backups, or jobs still waiting at Relay. The confirmation dialog shows the `ready` path and deletion scope.

After a new Relay package is successfully applied and acknowledged, Receiver automatically deletes older local received packages (identity JPGs, OCR values, PDF page JPGs, manifests and deletion trash) and all files/jobs currently under the configured scanner `ready` folder. It clears the old scan/wait/completed lists and undo history, then shows only documents from the newly received package. This can cancel an older scan waiting in `ready`. Already-applied SK/KT target files and their backups are retained, as are jobs still waiting at Relay. The document tab header and status bar identify this automatic replacement behavior.

## Receiver screen and local PDF scan queue

The Receiver separates **신분증 / 접수 결과** from **서류 스캔 대기열**. The identity tab uses the central OCR field labels with a large identity preview and a selector for received jobs. On the document tab, each PDF is shown as its own folder row. Double-click a row to page through its converted JPGs, then use **목록으로** to return.

If a received OCR value needs correction, choose **값 수정**, edit the fields and identity type, then choose **수정 적용**. SK regenerates the local `sk_report.txt` and backs up its previous version. KT updates the exact `T_SCAN_PAPER` row recorded when that job was first applied, rewrites `ORG.jpg`/`CR.jpg`, and keeps database and image backups. Receiver writes an audit trail to `backups/receiver-corrections.json` and updates the displayed job values. Corrections apply only on this Receiver; they are not sent back to the central PC. Older KT jobs whose applied marker has no target row ID cannot use this correction action, to avoid changing a different intake row.

New PDFs first appear in **스캔 서류 대기열**. Select one or more folders and choose **스캔할 서류로 이동 → (ready 등록)**, or drag them to **스캔할 서류**. That move immediately copies each PDF's JPG pages and manifest into its own job folder under the virtual scanner's `ready` directory; there is no second staging button. The Receiver displays the staged documents in **스캔할 서류** and the TWAIN source returns them in list order. Move a staged document back with **대기열로 내리기** only after its scan has completed. Reorder either panel with its up/down buttons. After TWAIN removes a job folder, Receiver marks that document complete and removes it from the active lists.

Select folders in either list and press **Delete**, or use **선택 서류 삭제**. The Receiver moves their page folders into a local per-job trash folder and removes them from both lists. Press **Ctrl+Z** or **삭제 취소** to restore the most recent deletion; the undo history survives a Receiver restart. Documents currently being scanned cannot be deleted. **서류 목록 초기화** permanently removes listed and trashed document pages and clears the undo history.

**서류 목록 초기화** asks for confirmation, blocks while the scanner `ready` folder has a job, then permanently deletes PDF page JPGs (including trashed pages) and clears those PDF entries from their local manifests. It keeps identity images, OCR values, SK report files, KT databases, and the scanner folder. This reset cannot be undone.

Folder names are normalized for display so Korean filenames created on macOS do not appear as separated consonants and vowels in the Windows Receiver.

Identity images, reviewed OCR values, locally applied work packages, previous SK reports, KT database backups, and scanner queue data remain on the workstations. Receiver does not automatically clean those local files. The Render relay is a separate cloud copy: its page payload is deleted on successful acknowledgement, while a small status record remains so the central app can confirm delivery.
